Counting what is already in the drawings

Unit count, types and areas, without counting them

Benoît
Today
He measures each unit with AutoCAD polylines, floor by floor, and types the result into a table. Every revision, again.
Should do
Read the numbers already written on the sheet and keep a running tally: how many units, which types, how many square feet per unit and per floor.
On screen
One table per question. Each table says which file it was read from and when.

Window schedule by floor

Benoît
Today
Window types are counted off the plans when the schedule is needed.
Should do
Count every window type on every floor, and show where a floor differs from the others.
On screen
A table with one row per window type, one column per floor, and a line flagging the floor that does not match.

How much brick, metal and glass on the elevations

Benoît
Today
Material quantities for the elevations are measured by hand when someone asks.
Should do
Add up each material per elevation, openings removed.
On screen
Material rows, one column per façade, totals in both square metres and square feet.

Zoning and building code

The article, in words anyone can act on

Guy
Today
Finding the article is easy. Understanding what it means for this project is the slow part, and the wording is open to reading.
Should do
For each rule that matters: quote it, say what the project measures, say what is required, and explain the gap in one sentence.
On screen
A list of articles on the left; on the right, the quote, two big numbers side by side (measured / required) and a short plain reading.

Say out loud what is missing instead of guessing

Guy
Today
Some answers cannot come from the drawings at all: lot area, distance to the property line, which code edition applies.
Should do
Never fake a verdict. Show the measurement, then name the missing inputs that block the conclusion.
On screen
A plain state on every article: fine, to check, missing input. One shared list of everything the project still needs.

The surveyor's plan under everything

Both
Today
The property lines are copied by hand from the surveyor's plan into the drawing. When the surveyor issues a newer one, nobody is sure which setbacks were measured from the old line.
Should do
Carry the surveyor's plan as its own layer, lined up with the building, and measure every setback and the lot coverage from it. When a newer plan arrives, say what moved and which numbers change with it.
On screen
An overlay that can be turned on over any floor, the property lines drawn on top of the building. Every distance to a line names the surveyor's plan, its number and its date. A new plan arrives as a revision, with the affected measurements listed.

Spot a minor exemption early

Guy
Today
A small gap, like a rear setback 30 cm short, is noticed late and costs a resubmission.
Should do
Flag the gap as soon as the drawing shows it, with the measured value and the article.
On screen
A clear badge on the article, and a shortcut to start the request.

A note the city planner can read

Guy
Today
Writing to the city is slow, and the exchange restarts every revision.
Should do
Assemble a draft: the articles, the measured values, the date, the open questions. The argument stays human.
On screen
One button, one draft to copy into an email. It never claims the project complies.

Stop redoing the ten-page code study

Guy
Today
About ten pages of code analysis, rewritten by hand for each project and each major revision.
Should do
Keep the study as a living list that updates when a drawing changes, and export it as the document.
On screen
The same article list, printed.

Changes and the reason behind them

Why was this changed?

Both
Today
A balcony moves, a window shrinks. Two years later nobody remembers who asked or why.
Should do
Refuse to record a decision without a reason. One line is enough, and it travels with the revision.
On screen
After any decision, a short prompt: pick a reason (client cost, structure, code, city, drawing error) and add a sentence. Entries with no reason are visibly marked.

What changed between two revisions

Benoît
Today
Version tracking is manual, so differences are found by eye.
Should do
List what moved since the last read: which units, which openings, which totals.
On screen
A change log on the project page, newest first, each line pointing at the unit it touched.

Show the knock-on effect of a change

Guy
Today
Clients ask for changes to cut cost; roughly seven in ten are small, and some arrive after the city submission.
Should do
When a change lands, say what it moves: glazed area, unit count, floor area, and which articles are affected.
On screen
A one-line before/after strip under the drawing, linked to the article it touches.

Drawings that disagree

2D plan against the 3D model

Both
Today
Benoît draws in AutoCAD, Guy retraces it in SketchUp. The two drift apart and nobody is told.
Should do
Compare them and list the differences, unit by unit, with both measurements side by side.
On screen
Plan and model next to each other, differences listed in a panel, each one openable.

Ducts, beams and columns in the same place

Benoît
Today
He opens the mechanical and structural drawings and hunts for conflicts by overlaying them mentally.
Should do
Overlay the engineers' drawings on the architecture and list where two things occupy one spot.
On screen
A list of conflicts, each with a small picture of the overlap, the two files, and the unit affected.

Things that should line up through the building

Benoît
Today
Roof drains, columns and shafts are checked floor against floor by hand.
Should do
Flag anything that is aligned on most floors and off on one.
On screen
Same conflict list, with the offset in millimetres and the floors compared.

Keeping the project on rails

A checklist that fills itself in

Guy
Today
Requirements live in handwritten notes and memory, carried from project to project.
Should do
Keep one list per phase, and let the drawings tick off and raise items on their own.
On screen
Phase tabs, plain checkboxes, and a short list of warnings counted from the drawings.

Dates and waiting

Guy
Today
Approvals and planner replies are waited on without a visible clock.
Should do
Show what is due, what is late and what the city has answered.
On screen
Three short lists: deadlines, warnings, exchanges with the city.

Showing the project to other people

Send a link instead of a file

Guy
Today
Sharing means exporting a PDF or a screenshot and emailing it. The next revision makes it wrong, and there is no way to know who is still reading the old one.
Should do
Share a link to what is on screen — one unit, one floor, one table, the whole project — that a client, an engineer or the city can open in a browser without an account.
On screen
A share button that copies the link to the current view. The link opens read-only, says which revision it is showing and when it was read, and can be switched off at any time.

Let the client turn the building

Guy
Today
Renders take a long time and the client still cannot look around.
Should do
Open the model in the browser so a client can orbit it and step into one unit.
On screen
The model beside the plan, with orbit, pan and zoom. Useful in meetings, not during production.

Numbers for the city committee, not a 3D show

Benoît
Today
Submissions need area tables; extra tools during early design only slow the work down.
Should do
Export the tables and the elevations as a clean document, with source file and date on the page.
On screen
An export button on every table. Nothing else added to the early design screens.
